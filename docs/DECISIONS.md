# Decision log

## Binding decisions (spec section 2, copied verbatim)

| ID | Decision |
|---|---|
| D-01 | Master is always the gRPC **client**; every executor is a gRPC **server** implementing one `Agent` service. |
| D-02 | Native agents are **single-session**. The connector is **multi-session** (one CDP connection per TV). |
| D-03 | CDP on TVs uses a **raw CDP backend** (JSON-RPC over WebSocket) by default. `chromiumoxide` is an optional backend (`cdp_backend: chromiumoxide`), because old TV Chromium builds break strict typed bindings. |
| D-04 | Config files are **YAML** (`serde_yaml_ng`), keys `snake_case`, unknown keys are errors. |
| D-05 | DSL line parsing: hand-written indentation scanner + `winnow` for line grammars. Diagnostics via `miette`. |
| D-06 | `'text' => P` is shorthand for `type 'text' => P`. **`type` REPLACES the field content** (clear, then enter text). Appending is a separate verb, `append`. |
| D-07 | Selector keys are exactly the device platform names (`web, webos, tizen, android, androidtv, ios, tvos`), with fallback chain `webos→web`, `tizen→web`, `androidtv→android`, `tvos→ios`. |
| D-08 | Comments in DSL files are lines starting with `//` (not `#`, which is valid CSS). |
| D-09 | `Check:` lines always **auto-wait** (poll) until the condition holds or the timeout elapses. There is no separate `waitfor`. |
| D-10 | `wait <duration>` and sleeping are **master-side only** and never sent over the wire. |
| D-11 | Logs: `StreamLogs` RPC is the single wire mechanism for executor logs. Host-side collectors (logcat, syslog) are master features. |
| D-12 | No session resume. After a transport failure the current Act fails with `TRANSPORT`; the master reconnects with a new session for the next Act. |
| D-13 | Android: **one** instrumentation APK; phone vs TV behavior is chosen at runtime from the handshake platform. Apple: shared `AgentCore` library, two UI-test bundles (iOS, tvOS). |
| D-14 | Apple server library: `grpc-swift` 1.x (NIO) while the OS floor is below the minimum of grpc-swift 2. Re-evaluate when the floor is raised. Verify in Phase 0. |
| D-15 | iOS `classChain` is NOT supported (it is a WebDriverAgent feature, not XCUITest API). |
| D-16 | `core` crate has **no dependency on the proto crate**; conversions live in `impresario-clients`. |
| D-17 | App reset policy `app_reset: per_act | per_play | never`, default `per_act`. |
| D-18 | If a gRPC server cannot run on a device (Phase 0 spike fails), fall back to length-prefixed protobuf frames over TCP behind the same `AgentClient` trait. Record the outcome in `docs/STATUS.md`. |
| D-19 | **No external platform tools at runtime.** The product never shells out to `adb`, `xcodebuild`/`xcrun`/`simctl`/`devicectl`, `ideviceinstaller`, `ares-*`, `sdb`, `tizen`, `openssl`, `ssh`, `scp`. Everything is a Rust implementation or an embedded/managed payload (ladder in §6.0). The only tolerated host prerequisite is an OS driver/service we cannot legally or technically ship (e.g. Apple's USB multiplexer service on Windows, WinUSB for Android USB); each such case is explicit in `impresario doctor` with a fix hint. |
| D-20 | **Global home** `~/.impresario` (`%USERPROFILE%\.impresario` on Windows; override with `IMPRESARIO_HOME`). Created on first run. No `init` command. |
| D-21 | **Device ≠ App.** A *device* is only a name, platform and connection info. An *app* is a separate definition (ids, package path, launch options). A run binds play → app → device(s). |
| D-22 | **Three-part DSL**: `*.scene` (locators, tabular), `*.theatre` (reusable stages), `*.play` (acts composed of stages, parametrizable). Stage names are globally unique. |
| D-23 | **Config is editable from the CLI/TUI**, at two scopes (`global`, `workspace`), losslessly (comments and ordering of hand-edited files preserved). |
| D-24 | **Jobs.** A run is a *job* with an id. Jobs can run in the foreground, be detached to the background, be listed, attached, tailed and stopped. Multiple jobs run concurrently; a device is leased by at most one job at a time (single-session native agents, D-02). |
| D-25 | **Two editor modes** from one source of truth: the language server (primary) and a standalone mode needing no server process. Grammar/diagnostic parity between them is enforced by a shared conformance corpus. |
| D-26 | **Tri-state probe verdicts** (`PASS`, `FAIL`, `UNVERIFIABLE`). `UNVERIFIABLE` is a first-class report status: `report.json`, JUnit (`skipped` with a message), console and HTML. The default policy is `unverifiable_policy: fail`; `warn` is opt-in per run (`--unverifiable warn`) and marks the step/act `unverifiable` while allowing the run to pass. |
| D-27 | **One evidence model and one verdict implementation** in `impresario-core::probe`: evidence classes, confidence thresholds, claim/assertion evaluation, property/provider/status vocabulary and the per-platform support matrix. Executors and host-assisted collectors produce evidence only; the master recomputes connectors' provisional verdicts so a Kotlin/Swift/JS executor cannot drift from the reference. |
| D-28 | **Probes are wire commands**: one `Probe` command with `kind = Showing | Player | Drm`, a selector, claims, assertions, sampling window, decode/source/coverage requirements, plus capabilities (`PROBE_SHOWING`, `PROBE_PLAYER`, `PROBE_DRM`). Not three RPCs. |
| D-29 | **`Platforms:` on plays/acts is removed** and replaced by **`Actors:`**: device names (or workspace-defined groups). Each actor resolves to a device whose platform drives support checks, selector columns, fallback chain and audience matching. `migrate` converts; there is no alias or deprecation window. |
| D-30 | **`Perform` is an interface; `Stage` is an implementation.** Several stages may share a name when their audience platforms do not overlap; uniqueness is `(stage name, audience platform)`. The interface is implicit and all implementations of one name must have identical parameter signatures. This supersedes TASK-2 section 8.3's globally-unique name rule and only D-22's uniqueness clause. |
| D-31 | **Audience matching is exact**: the device's platform must equal the declared audience platform. There is no `webos`-to-`web` or `androidtv`-to-`android` fallback; the selector fallback chain (D-07) is unaffected. |
| D-32 | **Resident runner** is the per-user background process (the TASK-2 section 3.5 daemon extended), started at user logon through the OS per-user mechanism, not a system service. It hosts jobs, schedules and watchers and survives closing the CLI/TUI. |
| D-33 | **New checks** `Check: Showing => Piece` (pixels/frames are really presented) and `Check: Player => Piece ...` (player/decoder/DRM truth). `is visible` keeps its old meaning (element exists in the view/DOM tree and is displayed per its own attributes); `Showing` adds decode, paint and occlusion proof. |
| D-34 | **Scene `Platforms:` headers stay** as declarations of the scene's selector columns. The `Actors:` rename applies only to plays/acts. This resolves TASK-3 section 13 item 1. |
| D-35 | **Tags propagate transitively** from theatres/stages to the acts that perform them, in addition to play-to-act inheritance and aggregation. This resolves TASK-3 section 13 item 2. |
| D-36 | **Audience granularity**: `Audience:` is file-level on theatres and may be narrowed per stage. This resolves TASK-3 section 13 item 3. |
| D-37 | **`Showing ... with` supports exactly `coverage`, `decoded` and `source`.** No other options are invented. This resolves TASK-3 section 13 item 4. |
| D-38 | **Unverifiable policy default is `fail`**, because a check that could not establish truth must not look green. `warn` remains available for exploratory runs. This resolves TASK-3 section 13 item 5. |
| D-39 | **Watchers support two modes.** No-gap mode holds the device exclusively for the watcher lifetime; gap mode takes a per-iteration lease and releases it between iterations. The mode is explicit configuration and must be shown in STATUS/TUI so it cannot silently starve scheduled jobs. This resolves TASK-3 section 13 item 6. |
| D-40 | **Acceptance material is public streams plus local fixtures.** No Netflix account, FairPlay asset, private license proxy or protected-frame capture is used. Hardware sessions that cannot be run in this environment are recorded as unverified in the HD ledger, never as passed. This resolves TASK-3 section 13 item 7. |
| D-41 | **The optional in-app hook ships as full SDKs** for Android, Swift and JavaScript, with reference fixtures. It is additive and never required for third-party apps. This resolves TASK-3 section 13 item 8. |
| D-42 | **Tray icon is optional best-effort**: implemented only where it is low-risk on the platform. Its absence must never change a run's result or lifecycle. This resolves TASK-3 section 13 item 9. |
| D-43 | **In-app hook transport is per platform, one JSON contract.** Web: `window.__impresarioHook.snapshot` set by `sdk/web/impresario-hook.js`. Android: `:impresario-hook` logs `IMPRESARIO_HOOK <json>` under `ImpresarioHook`; the driver reads the newest line with shell identity and ignores another package's or >60 s old snapshot. Apple: `ImpresarioHook` POSTs to the runner's `127.0.0.1:47831/hook`; `HookReceiver` caches the newest snapshot. All are debug-only, additive and optional; a missing hook only lowers achievable confidence, never changes a play or turns a claim into an invented PASS. |

## Implementation decisions (made here; the spec leaves them open)

| # | Decision |
|---|---|
| I-01 | Edition 2021, `rust-toolchain.toml` channel `stable`; every dependency pinned to an exact version in the workspace `Cargo.toml`. |
| I-02 | Protoc resolution for `build.rs`, in order: `$PROTOC` as a file; `$PROTOC/bin/protoc[.exe]` (the environment here points `PROTOC` at a directory); `protoc-bin-vendored` for hermetic builds. `PROTOC` is set for the child process only. |
| I-03 | Interpolation recognises only the exact forms `${env.IDENT}` and `${var.IDENT}`. Any other `${`-sequence is literal text. |
| I-04 | A duplicate `Var:` declaration in one play is **last-wins** (documented, tested). |
| I-05 | `IMP-DSL-012` (missing selector), `IMP-DSL-013` (unsupported action/key/check) and `IMP-DSL-017` (scene not applicable) are reported by `validate` (against every distinct configured device platform) **and** by the planner at plan time. |
| I-06 | `buf.gen.yaml` is a documented placeholder: proto code generation is per-language (Rust `build.rs`, Gradle protobuf plugin, Swift scripts). `buf.yaml` disables the lint rules that conflict with the verbatim contract (`SERVICE_SUFFIX`, `ENUM_VALUE_PREFIX`, `PACKAGE_VERSION_SUFFIX`, `RPC_REQUEST_RESPONSE_UNIQUE`, `RPC_RESPONSE_STANDARD_NAME`). |
| I-07 | `docs/PARITY.md` is generated from `impresario-core::support` (single source of truth) so it can never drift from the planner; a consistency test lands with the docs work. |
| I-08 | `validate [PATH...]` with explicit paths validates exactly those files/directories; when no `.scene` file is among them but plays are, the configured `scenes_dir` is loaded as the scene index so play resolution works. |
| I-09 | `agent_address` is required for `tvos` devices: Bonjour discovery is not implemented, so no configuration can enable it (help text says so). |
| I-10 | Filesystem errors while reading DSL/config files are reported with `IMP-CFG-003` (the catalog has no dedicated code for I/O). |
| I-11 | `init` refuses to overwrite existing files without `--force` and exits `2`; created/updated paths are printed to stdout. **Superseded by I-102.** |
| I-12 | Not-yet-implemented commands fail loudly with a message and exit `2`. `run` and `devices check` graduated in phase 3; `lsp` is the last stub — the current state is in `docs/STATUS.md`. |
| I-13 | miette rendering happens at the CLI boundary only: `impresario-master::render` converts the character-based `Span` to a byte range, attaches the source text and a label. `core` stays without file contents. |
| I-14 | The "did you mean" helper (`suggest`) lives in `impresario-core::diag` and compares case-insensitively (edit distance on lowercased text, threshold 2). |
| I-15 | `timeout` is not accepted on `key`, `back`, `wait`, `screenshot`, `app` lines (`IMP-DSL-022`); the parser rejects it at parse time. |
| I-16 | Lint `IMP-DSL-020` applies to scene and piece names (UpperCamelCase recommended); the hint names the converted form. |
| I-17 | An unset `${env.NAME}` is a plan-time error (`IMP-DSL-014`) whose help names the variable and says to set it before running; resolved env values are recorded as redaction secrets (spec 5.6). |
| I-18 | `app_reset` mechanics: the *first* reset of a run issues `AppControl{LAUNCH, clear_data}` (`clear_data` from the device's `options.clear_app_data`); every later reset issues `RESTART` with the same flag. Under `app_reset: never` no app-control command is ever sent — including the one a retry would otherwise do. |
| I-19 | Retries: `--retries n` allows up to `1 + n` attempts per Act; each retry starts with the app reset (I-18) and reconnects (fresh prepare/handshake/session) when the session died; an Act that passes after a failure is `flaky: true` and counts as passed. |
| I-20 | A `Screenshot` result that is `ok` with empty PNG bytes passes without writing a file. |
| I-21 | Exit codes: `130` interrupted; `3` when any device has a device-level error, or when the *final* attempt of a failed Act failed with an infrastructure-class code (`TRANSPORT`, `DEVICE_UNAVAILABLE`, `UNAUTHENTICATED`, `ALREADY_IN_USE`, `PROTOCOL`, `INTERNAL`) and produced zero wire step results; else `1` when any Act failed; else `0`. `TIMEOUT` is a test failure (`1`); any wire result, even a failed one, counts as "something ran". |
| I-22 | `--fail-fast` cancels one global token: no new Acts start anywhere; in-flight steps finish their current command; other devices stop at the next command boundary with remaining steps `aborted` and unstarted Acts `skipped`. First Ctrl-C is the same stop plus `Cancel` for the in-flight command (by id, given 3 s to settle); pending Acts are `aborted`, the report is `interrupted`, the exit code 130; a second Ctrl-C exits the process immediately with 130. |
| I-23 | Reporters: default `[console, junit, json]` (config `reporters`); `--reporter` overrides with a comma list (duplicates collapse; unknown or empty list exits 2); console color iff stdout is a terminal and `--no-color` is absent. Logging goes to stderr: `RUST_LOG` wins, else `-v` → `debug`, `--quiet` → `error`, default `warn`; a malformed filter falls back to that default instead of failing. |
| I-24 | Failure capture is best effort and never fails the run: the screenshot budget is capped at 10 s (master deadline); an alive session gets a `Screenshot` command, a closed one falls back to the out-of-band `CaptureScreenshot` RPC (spec 7.2.9); a missing SCREENSHOT capability skips it silently; the last 200 host+agent log entries are attached, already redacted. |
| I-25 | CLI selection: `--device` names keep the order given, duplicates collapse, `all`/absent selects every configured device in config order, an unknown name exits 2; `--play` accepts files, directories and globs (backslashes normalized to `/`, expanded relative to the workspace), and the resolved list is sorted and deduplicated (so play order is alphabetical by path). |
| I-26 | Screenshot layout: files live under `<run-dir>/screenshots/<device>/<name>.png` (spec 8.4 is explicit; 5.6's `report_output/screenshots/<run-id>/…` phrasing is superseded), and the report references them relative to the run directory as `screenshots/<device>/<name>.png`; the device directory is `sanitize_file_name(device.name)` and names are sanitized to `[A-Za-z0-9._-]`, ≤ 80 chars (spec 5.6). The html reporter reads the files back for base64 embedding and degrades to the plain path when a file is missing. |
| I-27 | `started_at` is UTC RFC 3339 with a `Z` suffix; run ids are `YYYYMMDD-HHMMSS-xxxx` (local time + 4 random hex chars). |
| I-28 | `report.json` carries an extra `exit_code` field (the code the process will return) on top of the Appendix B schema. A reporter write failure is reported on stderr and turns a would-be exit 0 into exit 3 — it never masks a worse code. |
| I-29 | `junit.xml` omits `timestamp` attributes: quick-junit wants a `chrono` value and no timezone crate is pinned; `started_at` lives in `report.json`. |
| I-30 | Capability gaps found at execution time: `app_reset != never` with Acts planned and a handshake lacking `APP_CONTROL` is a device-level `UNSUPPORTED_ACTION` raised before any Act (all Acts `aborted`, exit 3); a planned `screenshot` on an executor without `SCREENSHOT` fails that step with `UNSUPPORTED_ACTION` before anything crosses the wire (exit 1). Both are listed in the parity matrix. |
| I-31 | Attempt-level setup failures (prepare/connect/handshake/session/reconnect/app reset) are recorded as an attempt with `step_index: 0`, empty `stages` and a `phase` detail (`prepare`, `connect`, `handshake`, `session`, `capabilities`, `app_reset`); only a failed *initial* establish sets the device-level `error` (all Acts `aborted`). |
| I-32 | `devices check` requires both config files (missing/invalid → exit 2), probes the selected devices in config order (prepare → connect retried for `agent_start_timeout_ms` → handshake → `Shutdown`, no `Session` stream), prints one `DeviceInfo` line per device and exits 3 if any probe failed. |
| I-33 | Connector binary resolution for web-family transports: `$IMPRESARIO_CONNECTOR_BIN`, else a sibling of the running master executable, else `impresario-connector` on `PATH`; a loopback `agent_address` with something already listening connects directly without spawning anything (which is what lets the mock-based tests run without a connector). |
| I-34 | Connector handshake payload from the master: `params.options` carries the device's `options` map (documented keys `cdp_backend`, `key_dispatch`, `page_match`, `clear_app_data`, `animations_disabled`, `agent_port`) plus the polling knobs `poll_interval_ms`, `scroll_max_attempts`, `focus_max_steps`. `CdpBackend::as_str`/`KeyDispatch::as_str` (`impresario-core::config`) render the config enums into the wire strings; the connector ignores unknown option keys. |
| I-35 | Chromium discovery order for `launch[:headless]`: `$CHROME_BIN` (must name a file), then `PATH` (`google-chrome`, `google-chrome-stable`, `chromium`, `chromium-browser`, `chrome`), then OS-specific well-known install locations (`launch.rs`); nothing found → `DEVICE_UNAVAILABLE` with an explanation. |
| I-36 | Connector process exit codes: `0` ok, `1` runtime failure (served session/browser error), `2` usage (bad CLI/flags). `Shutdown` of an unknown session id is `Ok` (idempotent; used by `devices check`); `Cancel` answers with a result for its **own** `command_id`: `ok` when it stopped an in-flight command, `PROTOCOL` when the target was unknown or already finished. |
| I-37 | Every Chromium the connector launches also gets `--disable-background-timer-throttling --disable-backgrounding-occluded-windows --disable-renderer-backgrounding` on top of the spec's flags (I-38). Headless/occluded renderers otherwise stop producing BeginFrames, so `scroll` events and rendering-dependent probes stall (observed as a fixture-suite flake; the same flags ship in Playwright). |
| I-38 | Page resolution (spec 10.3) as implemented: an endpoint without `/devtools/page/` resolves via `GET /json/list` (fallback `/json`), keeps `type == "page"`, matches `page_match` against the URL or title substring and requires exactly one candidate (else `DEVICE_UNAVAILABLE` listing them); the page websocket's host:port is rewritten to the endpoint's. `launch[:headless]` spawns Chromium with `--remote-debugging-port=0 --user-data-dir=<temp> --no-first-run --no-default-browser-check --disable-background-networking about:blank` (+ `--headless=new`), parses `DevTools listening on ws://...` from stderr (30 s budget) and owns the process/temp profile until teardown. Resolution budgets: 15 s after `launch`, 5 s for an existing endpoint. |
| I-39 | The `chromiumoxide` backend connects at browser level, so it needs the browser websocket from `/json/version` (`webSocketDebuggerUrl`); when the endpoint exposes none the handshake fails `DEVICE_UNAVAILABLE` naming `cdp_backend=raw` as the alternative. It drives the chromiumoxide `Handler` stream in a task, waits up to 10 s for the resolved page target (by target id, else `page_match`, else exactly one), enables `Runtime`/`Log`, pumps console from `EventConsoleApiCalled`/`EventEntryAdded`, and maps CDP errors: `-32601`/`wasn't found` → `UNSUPPORTED_ACTION`, `JavascriptException` → `INTERNAL`, `Timeout` → `TIMEOUT`, everything else → `TRANSPORT`. `close()` aborts its tasks. |
| I-40 | The connector's DevTools HTTP GET (no HTTP dependency) frames replies by `Content-Length` or chunked encoding instead of waiting for EOF: Chrome keeps the connection open even though the request sends `Connection: close`. Budget 5 s, 4 MiB cap. |
| I-41 | Probes that act on an element (click, longpress, focus, type/append/clear, select) scroll it into view inside the probe before judging visibility/hit state (spec 10.3 "scroll into view"); `visible`/`hidden` checks keep the 6.4 definition (displayed, non-zero rect, intersects the viewport). Off-viewport elements are therefore interactable rather than `NOT_INTERACTABLE`. |
| I-42 | `window.__impresario` is injected idempotently before **every** command (10.3), and `probe` self-heals once (re-inject + retry) when a helper call fails: page discovery can name a page before its first document commits, and any navigation drops the helper between injection and evaluation. |
| I-43 | The ES5 helper reaches into **open** shadow roots: lookup walks shadow hosts, `activeElementDeep` pierces them for focus, and hit tests accept composed ancestors (needed by a shadow contenteditable fixture). Closed shadow roots remain unreachable (script cannot see them) and are documented as such. |
| I-44 | Text entry (10.3): focus + native value setter + `input`/`change`, verified by reading the value back; a mismatch falls back to select-all + `Input.insertText` (`Backspace` for `clear`); still wrong → `NOT_INTERACTABLE` with `expected`/`observed`/`selector` details. Contenteditable: focus, selectAll (replace) / collapseToEnd (append) / `clearContent` (clear), then `Input.insertText`. `type` REPLACES (D-06), `append` appends, `clear` empties. |
| I-45 | Scrolling: `web` performs one DOM step per `count` (80% of the container's visible extent; `window` when no container is given, else the element's `scrollTop/scrollLeft`); `webos`/`tizen` press a D-pad key once per `count`. `scrollto` goes down first and runs one upward phase only after the container reached its end; a missing explicit container is `ELEMENT_NOT_FOUND`; exhaustion is `ELEMENT_NOT_FOUND` with `details.scroll_attempts`. |
| I-46 | Web `longpress` is mouse `pressed` → hold `duration_ms` (default 1000) → `released` (the spec's ◐ "mouse hold"); on web TVs with `key_dispatch: js` the fallback cannot hold a key, so it dispatches one down/up pair and pauses — recorded in `docs/DEVICES.md` (Phase 8). A session drives exactly one page: `window.open`/`target=_blank` popups are not followed; `launch` opens `about:blank` and `app launch` navigates that page to `app_url`. |
| I-47 | Fixture `file://` URLs must strip the Windows verbatim prefix (`\\?\`) produced by `Path::canonicalize` — Chromium silently ignores `file:////?/D:/...` and opens the new-tab page instead (found while building the suite). The Phase 4 acceptance suite (`crates/impresario-connector/tests/fixtures_suite.rs`) drives the proto client directly (the connector keeps "no other edges"), uses one Chromium per fixture page, and skips cleanly when no Chromium is installed. |
| I-48 | Android modules build with AGP 9.4.1 and its **built-in Kotlin** support: Android modules do not apply `org.jetbrains.kotlin.android` (applying it conflicts with AGP 9) and take `jvmTarget` from `compileOptions` (Java 17). `:agent-core` stays a pure Kotlin/JVM module (`org.jetbrains.kotlin.jvm` 2.4.21 + `com.google.protobuf` 0.9.6, protoc 4.36.2) so the dispatcher/server tests run as plain JVM tests. Gradle 9.6.0 wrapper. Generated proto classes are `implementation`-scoped in `:agent-core`, so a module whose *public* API uses them (`:driver-uiautomator` with `SelectorStrategy`) declares `protobuf-java` itself. |
| I-49 | Android package layout, chosen to match the Rust `AdbTransport` constants: the stub app's `applicationId` is `com.impresario.agent` (its Kotlin namespace stays `com.impresario.agent.stub`, but runtime view ids use the applicationId — I-58); the instrumentation APK package is `com.impresario.agent.test` — the module *namespace* is set to that value because AGP names a standalone `com.android.test` module's APK after the namespace, not `<app id>.test`; runner class `com.impresario.agent.AgentRunner`; JUnit runner `androidx.test.runner.AndroidJUnitRunner`; `android:targetPackage` is merged as the stub's applicationId (`com.impresario.agent`). Both APKs checked with `aapt dump badging` (build-tools 36.1.0). |
| I-50 | The instrumentation process *is* the target app's process: since the stub is the target, the agent runs inside `com.impresario.agent`. Consequences: (a) `AdbTransport`'s pre-start `pm clear` and teardown `am force-stop` on `AGENT_PACKAGE` are correct — they stop the agent itself; (b) driving the stub from the master must use `app_reset: never` (a `LAUNCH`/`RESTART` with `clear_data`, or `terminate`, would kill the agent); (c) real apps under test keep their own processes, so this only constrains the stub target. |
| I-51 | `UiAutomatorDriver` mapping (spec 11.4): `ANDROID_ID` → `By.res(pkg, id)` (short names expanded with the app id), `TEXT` → `By.text`, `TEXT_CONTAINS` → `By.textContains`, `ANDROID_DESC` → `By.desc`, `ANDROID_CLASS` → `By.clazz`. `LAUNCH` uses `PackageManager.getLaunchIntentForPackage` + `FLAG_ACTIVITY_NEW_TASK|FLAG_ACTIVITY_RESET_TASK_IF_NEEDED` (same observable behaviour as the spec's suggested `monkey` command, and it selects the activity the launcher would); `TERMINATE` = `am force-stop`, `CLEAR_DATA` = `pm clear`. `type`/`append`/`clear` go through `setText` with a read-back; mismatch falls back to select-all + `input text '<escaped>'` (ASCII only, `UNSUPPORTED_ACTION` otherwise); TV longpress = a timed `UiAutomation.injectInputEvent` hold after D-pad focus (down → `FLAG_LONG_PRESS` repeat → up, ≥ 600 ms — supersedes the earlier `input keyevent --longpress 23`, which never elapsed the view's long-press timer, I-66). Crash detection: target process gone (`pidof`) or an `android:id/aerr_*` dialog → `APP_CRASHED`, with a `wasLaunched` guard so "app not running before its first launch" is not a crash. `deviceInfo` = product name (`ifBlank` → `Build.MODEL`), `Android`, `Build.VERSION.RELEASE`, display size/density, runtime `UiAutomator2`. |
| I-52 | `UiDriver.find` returns **all** matches (`count` counts them); the *dispatcher* applies `index` (0-based, negative = from the end) against that list, which is why the executor passes `index = 0` (helper `lookup()`) to the driver at every call site: index selection lives in exactly one place. Selector text in messages uses `SelectorSpec.describe()` (`strategy name:value[#index]`). |
